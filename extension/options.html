Privacy

Encrypted message bodies, attachments, and inline images are withheld from MCP clients by default. Opaque-signed S/MIME messages are also withheld while encrypted message access is off. Thunderbird may still decrypt S/MIME messages locally. Enabling encrypted message access exposes decrypted content to MCP clients and their AI providers, and allows direct replies and forwards when skipReview is permitted. While it is off, search and recent-message tools show the outer subject without a preview for messages Thunderbird has recorded as OpenPGP-encrypted, searches do not match them, and displayMessage refuses encrypted messages. Thunderbird provides no reliable encryption marker for all message headers, so some cached subjects may still contain decrypted protected headers.

When mail account access is restricted, calendars and address books are blocked unless you allow them below. These permissions allow access to all calendars or all address books, including changes. With unrestricted mail account access, their behavior is unchanged. These settings can only be changed here.

Authentication

Stable token mode keeps the same token across restarts. If the connection file leaks, the token stays valid until you regenerate or clear it. Changes apply next time the MCP server starts. The stored stable token is cleared on uninstall only while the add-on is enabled (best effort). If you disable the add-on before uninstalling, regenerate the token before using it again.

Send Safety

This setting is enabled by default. While enabled, MCP clients requesting skipReview: true on sendMail, replyToMessage, forwardMessage, createEvent, or createTask are rejected; the review window or dialog remains available. Adding event attendees is blocked. Events with attendees other than the calendar user are read-only through MCP: updates and deletions, including individual occurrences, are rejected even when attendees are omitted from the request. Exchange/Owl or CalDAV may email invitations, updates, or cancellations with the event title and description without review. Disabling this setting allows these writes and skipReview.

Filter Send Actions

Disabled by default. Enabling this lets MCP clients create, change, and run filters that forward messages or reply from templates without a compose review window. This setting is independent of Block skipReview.

Turning this off does not disable saved filters or stop Thunderbird from running them automatically. You can still disable or delete existing Forward/Reply rules through MCP.
